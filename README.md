# JAY.OS: Jay Dhangar's portfolio

A static portfolio generated from one JSON file, with a serverless RAG assistant (Ask Jay.OS)
that answers questions about the work with citations. Vanilla HTML/CSS/JS, no framework.

## Structure

```
data/portfolio.json          ALL content (single source of truth)
src/index.template.html      page shell with <!-- @slot --> markers, no content
build.js                     JSON + template -> index.html (static, crawlable)
index.html                   GENERATED. Do not edit by hand.
public/                      GENERATED deploy output (git-ignored): what Vercel serves
assets/render.js             shared HTML renderer (used by build.js and the browser)
assets/rag.js                chunking + BM25 retrieval (used by the browser and the API)
assets/app.js                interactions: Ask Jay.OS, console, inspector, lab filters, tabs
assets/styles.css            visual system
assets/fonts/                Geist + Geist Mono, self-hosted (SIL OFL, see OFL.txt)
assets/mark.svg              brand mark (inlined in the sidebar by build.js; source for the PNG icons)
assets/favicon.svg           16px tab icon (no tile; adapts to light/dark tab bars)
assets/og.png, *.png icons   social preview + PNG icons (generated by scripts/make-og.js)
api/ask.js                   Vercel function: health check, retrieval, Groq generation, limits
scripts/dev.js               local server: static files + the real API, rebuilds on change
scripts/make-og.js           regenerates og.png and PNG icons from portfolio.json
vercel.json                  runs `node build.js` on deploy
```

## Editing content

1. Edit `data/portfolio.json`.
2. Run `node build.js` (or keep `node scripts/dev.js` running, which rebuilds automatically).
3. Commit `data/portfolio.json` **and** the regenerated `index.html`, then push.

Vercel also runs `node build.js` on every deploy, so the live site is always built from the JSON.
Committing `index.html` keeps the repo previewable without a build step.

| Field | Drives |
| --- | --- |
| `profile`, `stats` | Hero and stats. Stats are Jay's own engineering numbers only (never company or product metrics); optional `detail` is the attribution line |
| `systems[]` | System rows/cards and the System Console. `status: "production"` makes a featured row |
| `architectures[]` | Engineering diagrams. `stages[].nodes[].xp` links a component to AI Lab cases |
| `lab[]` | AI Lab experiments. `kind`: `incident` = observed failure, `risk` = designed against |
| `thinking[]` | Expandable principles (`evidence` is a list, `related` are lab ids) |
| `sections`, `site` | Section copy, and `<title>` / description / social metadata |

## Local development

```
node scripts/dev.js          # http://localhost:3000, uses GROQ_API_KEY from .env if present
```

Without a key, Ask Jay.OS runs in local retrieval mode and says so in the UI.

## Ask Jay.OS

1. `portfolio.json` is split into ~145 passages (`rag.js`).
2. The question is ranked with BM25 (weighted query expansion; follow-ups reuse the previous question).
3. `api/ask.js` sends the top 6 passages to Groq with a cite-only-these-passages prompt.
4. The UI shows the answer, citations (each `[n]` is checked against the returned passages),
   the retrieval trace with BM25 scores, and measured retrieval / generation / total time.
5. If the API is unavailable, rate limited, or not configured, the browser answers from the same
   passages locally and shows the reason.

The status badge ("Assistant online" / "Local retrieval mode") comes from `GET /api/ask`,
which reports only whether an LLM is configured, never any key or secret.

## Environment variables (Vercel → Settings → Environment Variables)

| Name | Required | Default | Purpose |
| --- | --- | --- | --- |
| `GROQ_API_KEY` | for LLM answers | none | Groq API key. Without it the assistant runs in local mode |
| `GROQ_MODEL` | no | `openai/gpt-oss-120b` | Groq model id. Groq retires models; a retired one shows as "model unavailable" |
| `ASK_RATE_LIMIT` | no | `10` | Requests per IP per window |
| `ASK_RATE_WINDOW_MS` | no | `60000` | Rate-limit window |
| `ASK_DAILY_BUDGET` | no | `400` | Max LLM calls per function instance per UTC day |
| `SITE_URL` | no | Vercel production domain | Absolute URL for canonical / `og:url` / `og:image` |

`SITE_URL` falls back to `VERCEL_PROJECT_PRODUCTION_URL`, which Vercel sets automatically, so
social previews get absolute URLs on deploy without extra config.

### Rate limiting: known limitation

Limits live in function memory. Vercel can run several instances in parallel and recycle them,
so the per-IP limit and daily budget are best-effort per instance, not global guarantees.
For a hard global limit, add a Vercel Firewall rate-limit rule on `/api/ask`, or back the
counters with a shared store (e.g. Upstash Redis). The spend ceiling that always holds is the
usage limit you set in the Groq console.

## Social preview and icons

`assets/og.png` (1200x630) and the PNG icons are rendered from `portfolio.json` and `assets/mark.svg`.
After changing the headline, stats, or mark (then run `node build.js` so `public/` gets the new files):

```
npm install --no-save playwright && npx playwright install chromium && node scripts/make-og.js
```

## Deploy

Import the repo in Vercel (framework preset **Other**). `vercel.json` sets the build command.
