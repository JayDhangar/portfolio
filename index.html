Observed failureRAGJay.OS

Synonyms outranked the entity

“Explain the architecture of ChristianAI” ranked the Media Suite and Mendle diagrams above ChristianAI's. “Does he know Kubernetes” matched an unrelated passage.
  1. Problem

    Ask Jay.OS ranks portfolio passages with BM25 before answering.

  2. Failure

    “Explain the architecture of ChristianAI” ranked the Media Suite and Mendle diagrams above ChristianAI's. “Does he know Kubernetes” matched an unrelated passage.

  3. Root cause

    Query expansion added synonyms at full weight, so generic terms outscored the one entity the visitor named. “know” wasn't a stop word.

  4. Fix

    Weighted expansions at 0.45 of the visitor's own terms, strengthened title matches, trimmed the architecture aliases, and added conversational filler to the stop list.

  5. Lesson

    Retrieval fails silently. Test with real questions and check what ranks first.

Observed failureAgentsTikTok Ads Agent

The API the agent needed wasn't reachable

Live Ads API access was unavailable: the OAuth authorization could not complete.
  1. Problem

    Build an AI agent that creates TikTok ads through the TikTok Ads API.

  2. Failure

    Live Ads API access was unavailable: the OAuth authorization could not complete.

  3. Root cause

    TikTok Ads uses OAuth with PKCE requirements and regional restrictions that blocked authorization for this app.

  4. Fix

    A mocked OAuth access token simulates authenticated requests to exercise error handling and retry decisions; conversation and ad configuration persist in state.json for deterministic, resumable runs.

  5. Lesson

    When an external API is out of reach, build against a faithful stand-in and make the agent's state resumable.

Misspelled and ambiguous queries weren't detected reliably, so they could land on the wrong assistant path.

  3. Root cause

Designed againstReliabilityMendle

Two rate limits, one error

Handled as one generic error, a rate limit either breaks the conversation or triggers retries that can never succeed.
  1. Problem

    Every Mendle response depends on a Groq call, and the provider enforces both per-minute and daily token limits.

  2. Failure mode

    Handled as one generic error, a rate limit either breaks the conversation or triggers retries that can never succeed.

  3. Root cause

    Per-minute and daily limits look alike but recover on completely different timescales.

  4. Fix

    Retry with backoff for per-minute limits; daily-limit errors are distinguished and handled without pointless retries.

  5. Lesson

    A retry policy is only as good as its error taxonomy. Classify failures before reacting to them.

Designed againstEvalsMendle

Fluent isn't relevant

Generated responses can drift off-topic, repeat earlier replies, or come out the wrong length while still sounding fluent.
  1. Problem

    In wellness conversations, an off-topic or repetitive reply is a real failure, not a cosmetic one.

  2. Failure mode

    Generated responses can drift off-topic, repeat earlier replies, or come out the wrong length while still sounding fluent.

  3. Root cause

    The generator doesn't check its own output against the conversation.

  4. Fix

    An embedding-based quality gate on every response: cosine-similarity relevance scoring, repetition checks, and length validation.

  5. Lesson

    Anything you can score, score before it reaches the user.

Designed againstInfraJobHunt AI

Scheduled searches vs. a free tier

Repeated and scheduled searches can exhaust the monthly quota, after which the source stops returning results.
  1. Problem

    Job alerts run on a schedule against a job-search API with a limited free tier.

  2. Failure mode

    Repeated and scheduled searches can exhaust the monthly quota, after which the source stops returning results.

  3. Root cause

    Every identical search is a new billable call, and nothing caps total monthly usage.

  4. Fix

    A ~20h persistent cache shared by identical searches, alerts capped at once per day, and a monthly budget (default 180 calls) that hard-stops before the free tier runs out.

  5. Lesson

    External quotas are a design constraint. Build the budget into the system.

Thinking

The principles I bring to AI engineering. Open one for the reasoning and the experiments behind it.

01

Guardrails are part of the product

Safety isn't a layer bolted on at the end. Intent classification, safety guardrails, and prompt-injection defenses shape what a system is allowed to do from the first request.In practiceIntent guardrails in ChristianAIinjection defenses and anonymity controls in Mendle

A guardrail added after launch is a patch on behavior users have already seen. Deciding what a system may do, which intents it serves and which content it trusts, belongs in the architecture.

In practice that means classifying before generating (ChristianAI's intent routing), treating retrieved text as data (Mendle's injection defenses), and enforcing privacy in the system rather than in a prompt (Mendle's anonymity controls).

02

Assume the model will fail

Rate limits, timeouts, and ambiguous input are normal operating conditions. Systems should retry, back off, and fall back instead of breaking.In practiceRetry/backoff with per-minute vs. daily limit handlingLLM classifier fallbackno-key fallbacks in ResuMate

LLM providers rate-limit, time out, and return unexpected output as a matter of course. The question isn't whether a call fails, but whether the product degrades gracefully when it does.

The useful move is classifying failures: a per-minute limit deserves a retry, a daily limit doesn't. The same idea runs through ResuMate, where every AI feature has a deterministic fallback, and this site, which answers locally when the LLM is unavailable.

03

Measure quality, don't eyeball it

If a response can be scored, score it. Relevance, repetition, and latency are numbers you can track and improve.In practiceEmbedding relevance scoringLLM-as-a-judgelatency oversight in Mendleretrieval tests for Jay.OS

Looking good in a demo doesn't survive real conversations. Relevance, repetition, and length can be computed on every response, so they should be.

Measurement applies to retrieval too: this site's assistant ranked the wrong architecture first until it was tested with real questions and the top result was checked.

04

Ground every answer

Models are most useful when they're connected to current, verifiable sources, and honest about what they don't know.In practiceWeb search with citationsRAG job matchingthis portfolio's own RAG assistant

A model's knowledge is frozen and unattributed. Grounding, whether web search or retrieval over known data, makes answers current and checkable, and citations let the user do the checking.

Grounding has costs: retrieved text is untrusted, and bad retrieval produces confident wrong answers. So grounding ships with injection defenses and retrieval tests.

05

Cost is an engineering constraint

Token spend, caching, and billing models are design decisions. Pricing should follow real usage, not guesses.In practiceListening-time meteringpricing recalibrated to OpenAI costsnarration cachingAPI budgets in JobHunt

Model calls, TTS generation, and third-party APIs cost money per use, so the billing unit, the cache, and the quota are part of the design, not an afterthought.

ChristianAI moved to listening-time metering and recalibrated pricing on measured OpenAI cost; JobHunt caps its job API with a persistent cache and a monthly budget; narration is pre-generated so cost and latency aren't paid on the user's first play.
